# 仅 Vector 分组的 DFX 分析

以下数据来自主配置 T=4096/H=5120/I=S=1792/E=32/K=8/EP=4、BF16、push、六项融合全开、训练态的实际 DFX 捕获。每个模式仅捕获一次完整训练步；这里的前向窗口不是完整模块计时，不用于替代独立 NPU Event 性能。

全部四个 rank 均通过 3721 个唯一前向 compute task 校验，拆分为 360 AIC + 3361 AIV，包含 1 个 terminate；没有丢失或重复。baseline 只有 20 个奇数 AIV 混合执行通信和计算；vector 实际启用 40 AIV，奇数核仅 Dispatch/Combine，偶数核仅激活、归并和终止。

表中为四个 rank 各自所有核累计时间的平均值，单位是核时间 ms，不能相加重构延迟。Vector 启用更多核后，新增核较早进入等待，累计 wait 上升并不等于完整模块更慢。各阶段自身 compute 工作量基本不变，20 个通信核与 20 个计算核各自的阶段并行度仍约为原来的 20；其收益取决于是否能覆盖原来的排队等待。

当前捕获中，Cube 上 routed GMM1/GMM2 仍占较长计算区间；Vector 分组没有缩短这些矩阵乘本身。激活任务拖尾缩短后，计算核最终仍需等待所有 Combine 与 shared down 满足 WeightedUnpermute 的依赖，说明后段依赖限制了新增核带来的重叠空间。该解释属于根据时间线和任务依赖推导，需结合非 DFX 的多轮 Event 数字判断收益。

现有 recorder 位于 entry ready 之后、completion 握手之前，因此 ready/completion 时长未被采集；entry skew 仅为握手后进入记录区间的偏差。各 rank、各核、各 stage、各专家 up 的详细等待与计算区间见 dfx_analysis.json。
